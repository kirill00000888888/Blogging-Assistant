# Чат-бот для создания и ведения блогов

Дипломный проект по теме: **«Разработка чат-бота для создания и ведения блогов»**.

Основной продукт проекта — Telegram-чат-бот, который помогает пользователю организовать работу над блогом: подобрать темы, составить контент-план, подготовить структуру поста, сделать сценарий короткого видео и проанализировать аудиторию. Веб-интерфейс используется как защищенная административная панель для тестирования сценариев, просмотра истории и сохранения удачных материалов.

Искусственный интеллект в проекте используется как вспомогательный модуль генерации рекомендаций. Основная задача системы — предоставить пользователю чат-бота и инструменты для ведения блог-контента.

## Основные возможности чат-бота

- `/start` - запуск бота и описание возможностей.
- `/help` - список команд.
- `/plan тема` - контент-план на 7 дней.
- `/ideas тема` - идеи публикаций и рубрик.
- `/post тема` - структура поста.
- `/video идея` - сценарий короткого видео.
- `/audience ниша` - анализ аудитории блога.
- `/clear` - очистка истории диалога.

Также в Telegram доступны кнопки быстрого выбора сценариев: `План`, `Идеи`, `Пост`, `Видео`, `Аудитория`.

## Состав системы

- `telegram-bot.js` - основной Telegram-чат-бот на Telegraf.
- `hf-chat.js` - модуль обращения к Hugging Face OpenAI-compatible router.
- `server.js` - Express-сервер защищенной веб-панели.
- `public/` - интерфейс веб-панели для тестирования и сохранения материалов.

## Роль веб-панели

Веб-панель предназначена не для обычных пользователей, а для администратора или разработчика чат-бота. Через нее можно:

- проверить состояние системы и настройки AI-модуля;
- посмотреть список поддерживаемых Telegram-команд;
- протестировать сценарии до запуска их в Telegram;
- сохранить удачные варианты ответов;
- экспортировать тестовый диалог;
- проверить авторизацию администратора.

Обычный пользователь работает с системой через Telegram-бота. Администратор работает через веб-панель.

## Пользователи Telegram

Для обычных пользователей отдельная регистрация в веб-панели не требуется. Telegram уже выполняет базовую идентификацию пользователя: бот получает `chat_id` и ведет отдельную историю для каждого чата.

История диалогов разделяется по `chat_id`. При первом сообщении бот автоматически создает запись пользователя и сохраняет ее вместе с историей в `data/bot-state.json`. Поэтому разные люди могут пользоваться одним ботом независимо друг от друга, а история не пропадает после перезапуска процесса.

Если нужно закрыть бота только для выбранных людей, можно указать Telegram ID через переменную:

```env
ALLOWED_TELEGRAM_IDS=123456789,987654321
```

Если `ALLOWED_TELEGRAM_IDS` пустой, бот работает в публичном режиме: написать ему может любой пользователь Telegram.

## Роль искусственного интеллекта

ИИ не является отдельным самостоятельным приложением. Он используется как вспомогательный сервис внутри чат-бота:

- чат-бот принимает команду пользователя;
- сервер определяет сценарий: план, идеи, пост, видео или аудитория;
- модуль AI формирует текстовую рекомендацию;
- бот отправляет результат пользователю;
- при недоступности внешнего API включается резервный шаблонный режим.

То есть основная система состоит из Telegram-бота, команд, сценариев, пользовательских сессий, веб-панели и модуля генерации. AI отвечает только за содержательную часть ответа.

## Архитектура

```text
Пользователь
  -> Telegram-чат-бот
  -> Node.js / Telegraf
  -> Модуль обработки команд
  -> Модуль генерации рекомендаций Hugging Face
  -> История диалога пользователя

Администратор
  -> Веб-панель с авторизацией
  -> Тестирование сценариев и сохранение материалов
```

## Требования

- Node.js 20 или новее.
- Telegram bot token от `@BotFather`.
- Hugging Face token с доступом к Inference Providers.

## Запуск Telegram-бота

```powershell
npm run telegram
```

После запуска откройте бота в Telegram и выполните `/start`.

## Запуск веб-панели

```powershell
npm start
```

Откройте:

```text
http://localhost:3000
```

Панель защищена авторизацией. Логин и пароль берутся из `WEB_ADMIN_LOGIN` и `WEB_ADMIN_PASSWORD` в `.env`.

## Переменные окружения

Основные:

- `HF_TOKEN` - токен Hugging Face.
- `HF_MODEL` - модель для chat completions.
- `HF_CHAT_URL` - URL роутера Hugging Face.
- `PORT` - порт веб-панели.
- `WEB_ADMIN_LOGIN` - логин администратора веб-панели.
- `WEB_ADMIN_PASSWORD` - пароль администратора веб-панели.
- `WEB_SESSION_SECRET` - секрет подписи cookie-сессии.
- `HF_STREAM` - `0` для стабильного JSON-режима, `1` для стриминга.
- `HF_TIMEOUT_MS` - таймаут запроса к Hugging Face.
- `HF_MAX_TOKENS` - лимит длины ответа.
- `HF_TEMPERATURE` - креативность модели.
- `HF_RETRY_QUALITY` - повторная генерация при подозрительном ответе.
- `LOCAL_FALLBACK` - резервный демонстрационный режим. При `1` бот выдает локальные шаблонные ответы, если Hugging Face недоступен или закончились credits.

Telegram:

- `TELEGRAM_BOT_TOKEN` или `BOT_TOKEN` - токен бота.
- `TG_MAX_DIALOG_MESSAGES` - размер истории Telegram-диалога.
- `TG_HANDLER_EXTRA_MS` - запас времени для долгих ответов модели.
- `TG_HF_TIMEOUT_MS` - отдельный таймаут Hugging Face для Telegram.
- `TG_HF_MAX_TOKENS` - отдельная длина ответа для Telegram.
- `BOT_STORAGE_FILE` - путь к JSON-файлу с пользователями и историями. По умолчанию `data/bot-state.json`.
- `ALLOWED_TELEGRAM_IDS` - список Telegram ID через запятую. Если пусто, бот доступен всем.

Ограничения веб-API:

- `CHAT_MAX_MESSAGES` - максимум сообщений в истории запроса.
- `CHAT_MAX_MESSAGE_CHARS` - максимум символов в одном сообщении.
- `RATE_LIMIT_WINDOW_MS` - окно rate limit.
- `RATE_LIMIT_MAX` - максимум запросов за окно.
- `TRUST_PROXY` - включать только за доверенным reverse proxy.

## Как объяснять проект на защите

Проект является чат-ботом для создания и ведения блогов. Telegram-бот выступает основным пользовательским интерфейсом. Пользователь взаимодействует с системой через команды и сообщения, получает планы, идеи, структуры постов и сценарии видео. Веб-панель является дополнительным административным модулем: она защищена авторизацией и используется для тестирования сценариев, просмотра истории и сохранения результатов.

Модуль искусственного интеллекта не является самостоятельной целью проекта. Он подключен как вспомогательный сервис, который формирует текстовые рекомендации на основе команд пользователя.

Если во время демонстрации Hugging Face возвращает ошибку про окончание credits, оставьте `LOCAL_FALLBACK=1` в `.env`. Тогда система продолжит отвечать по локальным шаблонам для основных сценариев, а на защите это можно объяснить как резервный режим работы при недоступности внешнего AI API.
